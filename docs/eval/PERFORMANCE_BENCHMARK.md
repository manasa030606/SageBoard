# Sageboard — Performance benchmark

> Measured on the development sandbox (shared CPU, PostgreSQL on the same host, no network latency), generated by `uv run python -m evals bench` and `uv run python -m evals run --mode oracle`. Treat the numbers as relative, not as production capacity. **No language-model time is included** (the oracle replaces the model); real end-to-end latency will be dominated by model calls, see the live-mode instructions in `docs/eval/README.md`.

## What is measured

| Measurement | How |
|---|---|
| Guard validation | `validate_sql` over every reference statement (54), 5 repetitions |
| Query execution | each reference query through the real read-only executor, database-side time, 5 repetitions; median per query, then distribution over queries |
| Query round trip | wall clock for `executor.run` including the EXPLAIN cost-gate pre-check |
| Pipeline end to end | question submitted → run finished, through the HTTP API, 62 cases, oracle model |

## Data volume

- **small**: customers 300, order_items 4,168, orders 2,267, payments 2,398, products 40
- **standard**: customers 3,000, order_items 48,141, orders 26,082, payments 27,833, products 160

## Cost gate against Cartesian products

The Guard now rejects these statements (`CARTESIAN_JOIN`). The probe bypasses the Guard to measure the second layer, the EXPLAIN cost gate (`EXECUTOR_MAX_PLAN_COST`, default 5,000,000), on its own.

| Statement | Scale | Guard | Cost gate / execution | Plan cost | ms |
|---|---|---|---|---|---|
| comma join, 2 tables | small | rejected | ok | n/a (ran) | 37 |
| CROSS JOIN, 2 tables | small | rejected | ok | n/a (ran) | 40 |
| comma join, 3 tables | small | rejected | stopped (COST_LIMIT) | 42,528,505 | 19 |
| join with ON (true) | small | rejected | ok | n/a (ran) | 452 |
| comma join, 2 tables | standard | rejected | ok | n/a (ran) | 1848 |
| CROSS JOIN, 2 tables | standard | rejected | ok | n/a (ran) | 1798 |
| comma join, 3 tables | standard | rejected | stopped (COST_LIMIT) | 55,410,848,810 | 2 |
| join with ON (true) | standard | rejected | stopped (COST_LIMIT) | 18,835,944 | 1 |

Reading: the cost gate alone does not stop every Cartesian product. A two-table `COUNT(*)` cross join is cheap enough for the planner to estimate under the ceiling, so it runs. That is why the structural Guard rule was added (D60) instead of relying on the cost estimate.

## Not measured here

- Real model latency, retries and tokens per question (needs live mode).
- Concurrent users: the harness is a single user, one question at a time.
- PDF rendering time and memory.
- Datasets larger than the `standard` demo (about 26 k orders, 48 k order lines).
